## 5.1 二次复审修复记录（2026-11-01）

对复刻源码逐文件复审后，发现并修复以下问题（已重新构建、自检 13/13、重截图验证）：

| 问题 | 现象 | 修复 |
|---|---|---|
| 「美化 SQL」破坏数据 | 旧实现先整体 `to_uppercase()`，会把字符串字面量 `'China'` 改成 `'CHINA'`，改变查询语义 | 重写为按引号状态扫描，仅大写**引号外**关键字，字符串/引用标识原样保留；自检第 12 项覆盖 |
| 「添加记录」在 NOT NULL 表失败 | 旧实现用 `INSERT ... DEFAULT VALUES`，对 `name NOT NULL` 等列直接报约束错误 | 改为按列构造占位值（数值 0 / 文本空串，UNIQUE 冲突时改用随机后缀重试） |
| 设置「删除前确认」无效 | 删除记录直接执行，未读取设置 | 记录删除改为经确认对话框（`Act::DeleteRow`），并刷新对应表页 |
| 应用内「数据脱敏」缺失 | 欢迎页宣称已解锁，但无页面入口（疏漏） | 新增「数据脱敏」页 + 菜单/工具栏/右键入口，实现 5 种脱敏规则 |
| 「数据同步 / 结构同步」缺失 | 文档曾称"入口覆盖"，实际无入口 | 新增「同步」页，支持数据同步（INSERT OR REPLACE）与结构同步（补建表/列 + 差异分析） |
| 「查询历史」无界面 | `store.history` 只在后台记录，无处查看 | 新增「查询历史」页（查看/打开复用/清空） |
| 删除行后网格不刷新 | 走对话框删除后表页数据不更新 | `process_act(DeleteRow)` 删除后刷新对应表页并清空选中行 |
