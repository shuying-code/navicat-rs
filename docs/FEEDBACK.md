# 使用反馈指南（如何提交高质量问题）

感谢使用 **navicat-rs**！为了让反馈能被**快速定位、复现和修复**，请在提交 issue 前花 2 分钟阅读本指南。

## 反馈入口

- **新建问题 / 建议**：<https://github.com/zhouyulong123/navicat-rs/issues/new/choose>
  - 🐞 **Bug / 问题反馈** —— 可复现的功能异常、崩溃、报错
  - 💡 **功能建议** —— 新功能或改进
  - ❓ **使用咨询 / 反馈** —— 用法、配置、一般性反馈
- 也可以直接在仓库顶部 **Issues** 标签页创建。若不确定属于哪类，选「使用咨询 / 反馈」即可。

## 处理节奏（更新频率）

- 维护者**每周集中处理 / 回复一次** issue（约每周更新一次）。
- 新提交的 issue 会先做**分类与去重**；能复现的会标记优先级并排期；缺少关键信息（无法复现）的会标注 `need-repro` 并请你补充。
- 请**不要重复提交**同一问题；补充信息请直接在原 issue 里追加评论。

## 提交前检查清单

- [ ] 已搜索 [现有 issues](https://github.com/zhouyulong123/navicat-rs/issues?q=is%3Aissue)，没有重复。
- [ ] 已查阅 [README](../README.md) 与 [FAQ](../README.md#常见问题faq)。
- [ ] 使用的是**最新版本**（见 [Releases](https://github.com/zhouyulong123/navicat-rs/releases)）；旧版本请先升级复测。
- [ ] 已移除 **密码 / 连接字符串 / 隐私数据**等敏感信息。

## 需要提供的关键信息（越全越好）

| 项目 | 说明 | 示例 |
|---|---|---|
| 版本 / 构建号 | Release 文件名 / commit | `v0.1.0 · 74d4d67` |
| 运行方式 | GUI / 容器镜像 / 源码构建 | `GUI（Windows 可执行文件）` |
| 系统与架构 | OS + CPU 架构 | `Windows 11 x64`、`macOS 14 arm64` |
| 数据库引擎 | SQLite / PostgreSQL / 其他（离线演示库） | `SQLite 内置示例库` |
| 复现步骤 | 一步一步，别人照做能重现 | 见下方示例 |
| 预期结果 | 你认为应该发生什么 | |
| 实际结果 | 实际发生了什么（可附截图/录屏） | |
| 日志 / 报错 | 终端或界面完整报错文本 | | 
| 最小样例 | 最小 SQL / 表结构（DDL）/ 连接类型 | 见下文 |
| 出现频率 | 必现 / 偶现（大约几次一现） | `必现` |
| 界面环境 | 主题 / 树缩放 / 窗口大小 | `午夜蓝 · 100% · 1600×980` |

### 复现步骤示例

```
1. 打开 navicat-rs（v0.1.0）
2. 左侧双击 customers 表
3. 点击「添加记录」
4. 期望新增一行；实际弹出 NOT NULL 约束错误
```

## 如何获取这些信息

- **版本号**：Release 文件名与 commit（仓库 Commits 页可见）。
- **日志 / 报错**：终端启动时的输出；界面弹窗的错误文本（用 ``` 包成代码块更清晰）。
- **最小复现样例（强烈建议）**：
  - **SQL**：能触发问题的最小语句。
  - **表结构**：相关表的 `CREATE TABLE`（DDL）。
  - **数据**：能复现的最小数据集（可脱敏）。
- **截图 / 录屏**：界面交互问题建议附截图（含左侧树与右侧内容区）或短录屏。

## 敏感信息脱敏

提交前务必替换：数据库密码、连接字符串、内网域名/IP、真实业务数据等，用 `xxx` 或示例值代替。

## 安全问题（漏洞）

请**不要**在公开 issue 中披露安全漏洞。请使用 GitHub 仓库 **Security → Report a vulnerability**（Private vulnerability reporting）私下上报，我们会优先处理。

## Issue 标签与处理流程

| 标签 | 含义 |
|---|---|
| `bug` | 已确认为缺陷 |
| `enhancement` | 功能建议 / 改进 |
| `question` | 使用咨询 |
| `need-repro` | 信息不足、暂时无法复现，等待补充 |
| `duplicate` | 与已有 issue 重复 |
| `wontfix` | 暂不处理（附原因） |

处理流程：**分类去重 → 复现确认 → 定优先级排期 → 修复并合并 → 在 Release/CHANGELOG 记录 → 关闭 issue**。
